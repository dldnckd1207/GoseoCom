## 1. 핵심 변경 요지

1. **파이프라인 흐름 재정의**
   - 기존: "게시글 작성 시 이미지 첨부 → OCR 자동 실행 → 자동 댓글"
   - 신규: **번역기(SFR-200)가 파이프라인 정식 진입점**. 게시판 자동 답변은 설정 ON 시에만 동일 파이프라인을 재사용.

2. **Phase 로드맵 재편**
   - OCR/번역 파이프라인을 **Phase 1로 당김** (이미지 1장 범위)
   - PDF 다중 페이지는 Phase 2
   - 인증(OAuth)도 **Phase 1로 당김** (비인증 글쓰기 차단을 일관되게 적용하기 위함)

3. **다중 게시판 도입 (Phase 1부터)**
   - 단일 게시판이 아니라 `boards` 테이블 기반 다중 게시판 운영
   - `board_type`: `LIST` / `IMAGE` / `QNA` (UI 렌더링 방식 통합)

4. **SFR 통합**
   - SFR-102(OCR) → SFR-200에 통합
   - SFR-103(AI 자동 댓글 파이프라인 결과) → SFR-205에 통합

5. **파일 처리 구조 분리**
   - `file` 테이블과 `file_map` 다형 매핑 테이블
   - 파일 업로드 API와 엔티티 생성 API 분리
   - 흐름:
     1. `POST /files` (multipart) → `file` 레코드 생성 → `file_id` 반환
     2. `POST /boards/:code/posts` body에 `file_ids[]` 포함 → `posts` 생성 + `file_map` 매핑 레코드들 생성
   - 다른 엔티티(`comments`, `book_pages` 등)도 동일 패턴 적용

6. **번역 단위 추상화**
   - `Book` + `book_pages` 구조
   - `book_type`: `QUICK` (Phase 1, 이미지 1장 자동 생성) / `USER_CREATED` (Phase 2, 사용자 등록)

## 2. Phase별 기능 확정

### Phase 1 (MVP)

**인프라**
- 모노레포 (apps/client, apps/server, apps/admin) — `apps/admin`은 디렉토리만 준비, 구현은 Phase 3
- Docker Compose (PostgreSQL 16, server, client)
- uv (Python), npm (Node)
- ID 채번 전략: 엔티티는 문자열 ID-GEN (`BOARD_00000001`), 로그/이력은 `BIGSERIAL`

**게시판 (A)**
- A1. 다중 게시판 스키마 (`boards` 테이블, `board_type` 컬럼)
- A2. 게시글 CRUD (`posts.user_id` FK)
- A3. 댓글 CRUD (`comments.user_id` FK)
- A4. 파일 업로드 + `file_map` 다형 매핑 (선업로드 → 매핑)
- A5-1. **LIST 유형 UI만** 구현 (IMAGE/QNA는 Phase 2)
- A6. 게시판 목록 조회
- A7. 비인증 글쓰기/댓글 차단

**AI 자동 답변 (B) — 텍스트 기반**
- B1. 텍스트 기반 자동 답변
  - 조건: `board.auto_reply_enabled=true` AND **댓글 0건** AND 작성 후 `board.auto_reply_delay_min` 경과 AND `auto_reply_status=pending`
  - 이미지 첨부 여부와 무관하게 텍스트(제목 + 본문)만 AI에 전달
  - 결과 댓글의 작성자는 AI 시드 계정 (`USER_00000000_AUTO`)
- B3. 게시판별 설정 컬럼 (`auto_reply_enabled`, `auto_reply_delay_min` 기본 5분)
- AI 시드 계정 2종: `USER_00000000_AUTO`(텍스트 자동 답변), `USER_00000000_PIPELINE`(Phase 2용 파이프라인 답변)

**고서 번역기 (C)**
- C1. 이미지 1장 업로드 → OCR (PaddleOCR 1순위, Google Vision 2순위)
- C2. AI 번역 (Gemini Flash 1순위, Claude Haiku 2순위, 직역/의역 분리)
- C4. Book + book_pages 스키마 선반영 (Phase 1은 `book_type='QUICK'`만, 이미지 1장 = Book 1 + Page 1)
- 번역기는 로그인 필수

**인증 (D)**
- D1. OAuth 로그인 (Google + Kakao 둘 다)
- D2. 세션/JWT 관리
- D3. 게시글/댓글 작성자 FK 연결
- D4. 비로그인 안내 화면 (라이브러리/번역기/글쓰기 등)
- 스키마: `users` + `user_oauth` 분리, `user_level` 기반 권한
  - 권한 레벨: `GUEST(0)` / `USER(10)` / `ADMIN(70)` / `SYSTEM_ADMIN(100)`
  - 개인정보 최소 수집: `email`, `name`, `profile_image_url`만 저장 (`phone`, `login_id` 등 미수집)

**라이브러리 (E)**
- E1. 내 번역 이력 UI — 단순 리스트 (탭 구분 없음)
  - 본인 소유 `books` 조회 (Phase 1엔 모두 `book_type='QUICK'`)
  - 제목 수정 가능, 보관은 영구, 수동 삭제만
  - 기본 제목 자동 생성: `"빠른 번역 YYYY-MM-DD HH:mm"`
  - 정렬: 최신순 기본, 제목순 옵션
  - 비로그인 접근 시 로그인 안내

**안전/운영 (G)**
- G2. 업로드 파일 검증 (이미지 타입, 최대 10MB, 게시판별 `board.attach_*` 설정 기반)

**로그 스키마 선반영**
- `login_log` 테이블 + OAuth 로그인 시 INSERT (조회 UI는 Phase 3)
- `admin_audit_log` 테이블 스키마만 선반영 (INSERT/조회 모두 Phase 3)

### Phase 2

**게시판 (A)**
- A5-2. IMAGE 유형 UI (카드/갤러리 뷰)
- A5-3. QNA 유형 UI (아코디언 뷰)

**AI 자동 답변 (B)**
- B2. 파이프라인 기반 자동 답변 (SFR-205)
  - `board.pipeline_enabled=true`인 게시판만 대상
  - 이미지 첨부 글에 대해 OCR + 번역 + 요약 포함한 답변 생성
  - 결과 댓글의 작성자는 AI 시드 계정 (`USER_00000000_PIPELINE`)

**고서 번역기 (C)**
- C3. PDF 다중 페이지 지원 (최대 100페이지 / 50MB, 서버에서 페이지 분할)
- C4 확장. USER_CREATED Book (사용자가 책 먼저 등록 후 이미지/PDF 추가)
- C5. 요약 / 키워드 / 빈도수
  - Book 단위 요약 (페이지 단위는 추후)
  - 번역 완료 직후 자동 실행 + DB 저장
  - 요약: LLM (Gemini/Claude)
  - 키워드/빈도수: `kiwipiepy` 로컬 형태소 분석 (LLM 미호출)
- C7. 번역 결과 수정 (**본인 소유 Book만**)
  - 직역/의역 인라인 편집
  - 수정 전 버전은 `page_revisions` 테이블에 append-only
- C8. 번역 결과 저장 / 공유
  - `books.share_token` (UUID 기반)
  - URL: `/s/:share_token`
  - 기본값 OFF, owner가 명시적으로 "공유" 활성화
  - 공유 링크는 열람 전용, 편집 불가
  - 비로그인 열람 허용

**라이브러리 (E)**
- E1 확장. 탭 구조 도입 — "내 책"(`USER_CREATED`) / "빠른 번역"(`QUICK`) 탭 분리
- E2. 즐겨찾기 — `books.is_favorite BOOLEAN` 컬럼 토글, 라이브러리에서 필터 제공
- 제목 검색 (제목만, 전문 검색은 Phase 3)

## 3. 주요 스키마 변경

### 3.1 users + user_oauth (신규)

```
users
├─ id                  VARCHAR(20) PK, ID-GEN (USER_00000001)
├─ email               VARCHAR(255) NOT NULL, UNIQUE
├─ name                VARCHAR(100) NOT NULL
├─ profile_image_url   VARCHAR(500) NULLABLE
├─ user_level          INT NOT NULL DEFAULT 10
├─ status_cd           VARCHAR(20) NOT NULL DEFAULT 'ACTIVE'
├─ use_yn              BOOLEAN NOT NULL DEFAULT true
├─ block_yn            BOOLEAN NOT NULL DEFAULT false
├─ blocked_at          TIMESTAMPTZ NULLABLE
├─ blocked_by          VARCHAR(20) NULLABLE (FK users.id)
├─ joined_at           TIMESTAMPTZ NOT NULL DEFAULT now()
├─ last_login_at       TIMESTAMPTZ NULLABLE
├─ left_at             TIMESTAMPTZ NULLABLE
├─ left_reason         VARCHAR(500) NULLABLE
├─ created_at / updated_at
└─ del_yn / deleted_at / deleted_by
```

```
user_oauth
├─ id                  VARCHAR(20) PK, ID-GEN (OAUTH_00000001)
├─ user_id             VARCHAR(20) FK → users.id
├─ provider            VARCHAR(20)  -- 'google' | 'kakao'
├─ provider_user_id    VARCHAR(255)
├─ provider_email      VARCHAR(255) NULLABLE
├─ created_at / updated_at
└─ del_yn / deleted_at

UNIQUE (provider, provider_user_id)
INDEX (user_id)
```

### 3.2 boards (기존 CMS 스키마에서 추림)

```
boards
├─ id                  VARCHAR(20) PK, ID-GEN (BOARD_00000001)
├─ board_code          VARCHAR(50) UNIQUE  -- URL slug
├─ board_name          VARCHAR(100)
├─ board_desc          VARCHAR(500) NULLABLE
├─ board_type          VARCHAR(20) DEFAULT 'LIST'  -- LIST | IMAGE | QNA
├─ notice_yn           BOOLEAN DEFAULT true
├─ comment_yn          BOOLEAN DEFAULT true
├─ attach_yn           BOOLEAN DEFAULT true
├─ attach_ext          VARCHAR(200) NULLABLE
├─ attach_size         INT DEFAULT 10          -- MB
├─ attach_count        INT DEFAULT 5
├─ list_count          INT DEFAULT 10
├─ auto_reply_enabled  BOOLEAN DEFAULT false
├─ auto_reply_delay_min INT DEFAULT 5
├─ pipeline_enabled    BOOLEAN DEFAULT false   -- Phase 2부터 실 동작
├─ sort_order          INT DEFAULT 0
├─ use_yn              BOOLEAN DEFAULT true
├─ created_at / updated_at
└─ del_yn / deleted_at
```

### 3.2a posts (게시글)

```
posts
├─ id                  VARCHAR(20) PK, ID-GEN (POST_00000001)
├─ board_id            FK → boards.id
├─ user_id             FK → users.id
├─ title               VARCHAR(200)
├─ content             TEXT
├─ view_count          INT DEFAULT 0
├─ comment_count       INT DEFAULT 0          -- 자동답변 대상 판별용 (캐시)
├─ auto_reply_status   VARCHAR(20) DEFAULT 'pending'  -- pending | completed | skipped
├─ auto_reply_at       TIMESTAMPTZ NULLABLE
├─ created_at / updated_at
└─ del_yn / deleted_at
```

- 첨부 파일은 `file_map`을 통해 연결 (`target_type='POST'`, `target_id=post.id`)

### 3.2b comments (댓글)

```
comments
├─ id                  VARCHAR(20) PK, ID-GEN (CMT_00000001)
├─ post_id             FK → posts.id
├─ user_id             FK → users.id          -- AI 시드 계정도 여기에
├─ parent_id           VARCHAR(20) NULLABLE, FK → comments.id  -- 대댓글 (Phase 1부터 지원)
├─ content             TEXT
├─ is_filtered         BOOLEAN DEFAULT false       -- Phase 3 G1
├─ filter_reason       VARCHAR(200) NULLABLE       -- Phase 3 G1
├─ filtered_at         TIMESTAMPTZ NULLABLE        -- Phase 3 G1
├─ filter_reviewed_by  VARCHAR(20) NULLABLE        -- Phase 3 G1, FK users.id
├─ created_at / updated_at
└─ del_yn / deleted_at
```

- AI 댓글: `user_id` = AI 시드 계정 ID (`USER_00000000_AUTO` / `USER_00000000_PIPELINE`)
- Phase 3 악성댓글 필터링 컬럼은 Phase 1 스키마에 선반영 (default 값으로 무해)

### 3.3 file + file_map (신규, 다형 매핑)

```
file
├─ id                  VARCHAR(20) PK, ID-GEN (FILE_00000001)
├─ storage_path        VARCHAR(500)
├─ original_name       VARCHAR(255)
├─ mime_type           VARCHAR(100)
├─ file_size           BIGINT
├─ file_ext            VARCHAR(20)
├─ created_at
└─ del_yn / deleted_at
```

```
file_map
├─ id                  VARCHAR(20) PK, ID-GEN (FMAP_00000001)
├─ file_id             FK → file.id
├─ target_type         VARCHAR(20)  -- POST | COMMENT | BOOK_PAGE | ...
├─ target_id           VARCHAR(20)
├─ sort_order          INT DEFAULT 0
├─ created_at
└─ del_yn / deleted_at

INDEX (target_type, target_id)
INDEX (file_id)
```

### 3.4 books + book_pages (신규, 번역기 도메인)

```
books
├─ id                  VARCHAR(20) PK, ID-GEN (BOOK_00000001)
├─ title               VARCHAR(200)  -- QUICK은 자동 생성
├─ book_type           VARCHAR(20)   -- QUICK | USER_CREATED
├─ source_type         VARCHAR(20)   -- IMAGE | PDF (Phase 1: IMAGE만)
├─ total_pages         INT DEFAULT 1
├─ owner_user_id       FK → users.id
├─ status              VARCHAR(20)   -- processing | completed | failed
├─ is_favorite         BOOLEAN DEFAULT false  -- Phase 2 E2
├─ share_token         VARCHAR(100) NULLABLE  -- Phase 2 C8 (NULL=공유 OFF)
├─ created_at / updated_at
└─ del_yn / deleted_at
```

```
book_pages
├─ id                  VARCHAR(20) PK, ID-GEN (BPAGE_00000001)
├─ book_id             FK → books.id
├─ page_no             INT
├─ file_id             FK → file.id   -- 원본 이미지 (⚠ 아래 노트 참조)
├─ ocr_text            TEXT
├─ ocr_engine          VARCHAR(50)    -- 'paddle' | 'google_vision'
├─ ocr_confidence      FLOAT
├─ literal_text        TEXT
├─ interpretive_text   TEXT
├─ translator_engine   VARCHAR(50)    -- 'gemini' | 'claude'
├─ status              VARCHAR(20)
├─ created_at / updated_at
└─ del_yn / deleted_at
```

> **⚠ book_pages ↔ file 연결 방식 미확정**
> - (A) `book_pages.file_id` 직접 FK: 단순하지만 `file_map` 다형 매핑 일관성 깨짐
> - (B) `file_map`(target_type='BOOK_PAGE') 경유: 다형 매핑 일관성 유지, 조회 시 JOIN 1단계 추가
> - Domain/ERD 리뷰 세션에서 확정 예정

### 3.5 page_revisions (Phase 2, C7 번역 수정 이력)

```
page_revisions
├─ id                  VARCHAR(20) PK, ID-GEN (REV_00000001)
├─ page_id             FK → book_pages.id
├─ literal_text        TEXT   -- 수정 전 직역
├─ interpretive_text   TEXT   -- 수정 전 의역
├─ edited_by           FK → users.id
└─ created_at
```

### 3.6 login_log (로그인 이벤트, 로그성, BIGSERIAL)

```
login_log
├─ id              BIGSERIAL PK
├─ user_id         VARCHAR(20) NULLABLE       -- 성공 시 채워짐, 실패 시 NULL
├─ provider        VARCHAR(20)                -- 'google' | 'kakao'
├─ provider_email  VARCHAR(255) NULLABLE      -- 로그인 시도 이메일
├─ ip_address      VARCHAR(45)
├─ user_agent      VARCHAR(500)
├─ result          VARCHAR(20)                -- 'success' | 'fail'
├─ fail_reason     VARCHAR(200) NULLABLE
└─ created_at      TIMESTAMPTZ
```

- Phase 1부터 INSERT 시작 (OAuth 로그인 시)
- 조회 UI는 Phase 3 관리자 페이지(F7)

### 3.7 admin_audit_log (관리자 작업 이력, 로그성, BIGSERIAL)

```
admin_audit_log
├─ id              BIGSERIAL PK
├─ admin_user_id   VARCHAR(20) FK → users.id
├─ action          VARCHAR(50)    -- 'BOARD_CREATE' | 'COMMENT_DELETE' | 'USER_BLOCK' | ...
├─ target_type     VARCHAR(20) NULLABLE  -- 'BOARD' | 'POST' | 'COMMENT' | 'USER'
├─ target_id       VARCHAR(20) NULLABLE
```

## 4. 권한 체계

```python
class UserRole(IntEnum):
    GUEST = 0           # 비로그인
    USER = 10           # 일반 사용자
    ADMIN = 70          # 앱 관리자 (게시판/댓글/게시글 관리)
    SYSTEM_ADMIN = 100  # 시스템 관리자 (로그 모니터링, 설정)
```

### 접근 영역
| 레벨 | 영역 |
|------|------|
| GUEST (0) | 게시글 읽기만 |
| USER (10) | 글/댓글 CRUD (본인 것), 번역기 사용, 라이브러리 |
| ADMIN (70) | 게시판 CRUD, 전체 게시글/댓글 관리, 자동답변 설정 |
| SYSTEM_ADMIN (100) | 로그 모니터링, 시스템 설정, 파이프라인 엔진 교체 |

### 구현
- `users.user_level INT`
- 데코레이터: `@require_level(UserRole.USER)` 등
- Phase 1에는 `@require_level(UserRole.USER)`까지만 사용, ADMIN 이상은 Phase 3에서 활성화

### 시드 계정

| 종류 | 레벨 | 방식 | 도입 Phase |
|------|------|------|-----------|
| AI 자동 답변 에이전트 (`USER_00000000_AUTO`) | 10 | DB seed (migration) | Phase 1 |
| AI 파이프라인 답변 에이전트 (`USER_00000000_PIPELINE`) | 10 | DB seed (migration) | Phase 2 |
| 최초 관리자 | 70 or 100 | env 변수로 이메일 지정 → 해당 이메일로 OAuth 로그인 시 자동 레벨 승격 (최초 1회만) | Phase 3 |
| 이후 관리자 | 70 | 기존 관리자가 관리자 페이지에서 권한 부여 | Phase 3 |

- `INITIAL_ADMIN_EMAILS=alice@example.com,bob@example.com` 같은 env 변수로 부트스트랩
- 한 번 승격되면 env 변경 없어도 유지
- 비상 복구: DB 직접 `UPDATE users SET user_level=100 WHERE ...`
