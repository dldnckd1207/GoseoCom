## 1. 목표

SFR-105(게시판 관리)로 구성된 게시판 위에서 동작하는 **게시글 / 댓글 CRUD**를 구현한다.

- 게시글 목록·단건 조회: GUEST 허용 (board `read_yn` / `guest_read_yn` 설정 따름)
- 게시글·댓글 작성·수정·삭제: USER 이상
- 수정·삭제: 본인 또는 ADMIN 이상 (BBR-05)
- 파일 첨부: 선업로드 방식, 게시판 정책(`attach_yn`, `attach_ext`, `attach_size`, `attach_count`) 검증
- Phase 1 제외: 좋아요, 비밀글, AI 자동 답변 실행

## 2. 범위

### SFR-101 API (10개)

| Method | Path | 인증 | 설명 |
|--------|------|------|------|
| POST | `/api/v1/posts/list` | GUEST | 게시글 목록 (board_code 필수, board_code 포함 응답) |
| GET | `/api/v1/posts/{post_id}` | GUEST | 단건 조회 + view_count++ + files[] |
| POST | `/api/v1/posts` | USER | 게시글 작성 (file_ids 선택) |
| PUT | `/api/v1/posts/{post_id}` | USER | 게시글 수정 (본인 or ADMIN, file_ids 전체 교체) |
| DELETE | `/api/v1/posts/{post_id}` | USER | 게시글 삭제 (본인 or ADMIN, Soft Delete) |
| POST | `/api/v1/boards/{board_code}/uploads` | USER | 게시판 파일 선업로드 |
| POST | `/api/v1/posts/{post_id}/comments/list` | GUEST | 댓글 목록 (Nested B, depth=1) |
| POST | `/api/v1/posts/{post_id}/comments` | USER | 댓글 작성 |
| PUT | `/api/v1/posts/{post_id}/comments/{comment_id}` | USER | 댓글 수정 (본인 or ADMIN) |
| DELETE | `/api/v1/posts/{post_id}/comments/{comment_id}` | USER | 댓글 삭제 (본인 or ADMIN, placeholder) |

## 3. 핵심 결정 사항

| 항목 | 결정 |
|------|------|
| JWT `name` 클레임 | Access Token에 추가 — `author_name` 스냅샷을 DB 조회 없이 처리 |
| view_count | atomic UPDATE (`view_count = view_count + 1`) |
| comment_count | 댓글 작성·삭제 시 atomic UPDATE. 삭제되지 않은 전체 댓글+대댓글 수 |
| PostHistory | 수정·삭제 시만 INSERT (CREATE 제외). 수정 전 title·content 보존 |
| 파일 수정 정책 | file_map 전체 교체. `dict.fromkeys(file_ids)`로 중복 제거 |
| 파일 보안 | `com_tn_file.del_yn=true` 거부. `file.created_by == user_id` 소유권 검증 |
| 댓글 구조 | Nested B — root에 replies 배열. depth=1 고정 |
| root 댓글 삭제 | placeholder 방식 (replies 유무 무관). `is_deleted=true`, content="삭제된 댓글입니다." |
| total (댓글 목록) | del_yn 무관 root 전체 수. replies는 root id 목록으로 별도 IN 쿼리 |
| 파일 타입 | 번역기: `image/*` 전용. 게시판: `attach_ext` 설정 따름 (PDF 등 가능) |
| attach_ext 검증 | Phase 1: `file_ext` 컬럼 기준. MIME 교차 검증은 Phase 2 이후 |

```

├── post_schemas.py       # PostListRequest, PostSummaryResponse, PostDetailResponse
│                         # PostCreateRequest, PostUpdateRequest
├── comment_schemas.py    # CommentListRequest, CommentResponse (Nested)
│                         # CommentCreateRequest, CommentUpdateRequest
```

## 6. 성공 기준

**정상:**
- 게시글 목록 → notice_yn=true 우선, created_at DESC, board_code 포함
- 게시글 단건 → view_count +1, files[] 포함
- 게시글 작성 → `POST_XXXXXXXX` 발급, author_name JWT 스냅샷
- 게시글 수정 → PostHistory INSERT, file_map 교체, 트랜잭션 롤백 보장
- 게시글 삭제 → Soft Delete, PostHistory INSERT
- 댓글 목록 → Nested B 구조, root 삭제 시 placeholder 포함
- 댓글 작성 → comment_count +1
- 댓글 삭제 → comment_count -1, placeholder 노출
- 파일 업로드 → `FILE_XXXXXXXX` 발급

**예외:**
- `read_yn=false` / `guest_read_yn=false` 게시판 접근 → 403
- `write_yn=false`, `comment_yn=false`, `reply_yn=false` 위반 → 403
- USER가 `notice_yn=true` 설정 / `board.notice_yn=false` → 403
- 타인 게시글·댓글 수정·삭제 → 403
- 삭제된 파일·타인 파일 첨부 → 404 / 403
- 첨부 개수·크기·확장자 위반 → 400
- depth=1 댓글에 대댓글 시도 → 403
- 파일 검증 실패 시 기존 첨부 유지 (트랜잭션 롤백)
