# Review: 커뮤니티 글 작성 화면 UI 정렬 Plan (#100)

**검토일:** 2026-05-13  
**추가 검토:** 2026-05-14  
**검토자:** Codex  
**대상 문서:** `docs/pdca/cellmin/1-plan/2026-05-11/community-write.md`

---

## 총평

Plan은 `/community/write` 화면을 목업에 맞춰 정렬한다는 목표와 변경 파일을 좁게 잡고 있어 구현 착수 기준으로는 충분하다. 특히 loader/action/API 로직을 건드리지 않고 UI만 정리한다는 범위 설정은 적절하다.

다만 현재 구현은 loader에서 받은 `boards` 데이터를 기반으로 게시판 선택지를 렌더링하고 있으므로, 문서의 "번역 / 질문 / 자유" 버튼 토글 요구사항이 하드코딩으로 해석되지 않도록 보완하는 것이 좋다. 또한 hidden input 기반 제출 방식은 초기 선택값과 검증 정책을 명확히 해야 구현 차이를 줄일 수 있다.

2026-05-14 수정본에서는 위 주요 지적 사항이 대부분 반영되었다. `boards` 기반 동적 렌더링, radio 기반 버튼 토글, `?board=` 초기 선택 정책, 타입 체크 검증 기준, 시대 필드 제외 후 전체 폭 배치가 명확해졌다.

이후 재수정본에서 `?board` 처리를 위해 loader 반환값을 추가하는 범위와 "loader 변경 제외" 문구의 충돌도 해소되었다. N-2는 action submit contract 유지와 `defaultBoard` 추가 반환으로 정리되었고, 제외 범위도 loader의 게시판 조회 로직 변경 금지와 `?board` 파싱 허용을 분리해 표현하고 있다.

---

## 발견 사항

### High - 글 유형 버튼이 하드코딩 요구로 해석될 수 있음

F-1은 `<select>`를 버튼 토글 그룹으로 변경하면서 항목을 "번역 / 질문 / 자유"로 적고 있다. 하지만 현재 `CommunityWriteView`는 loader에서 받은 `boards`를 기반으로 select option을 렌더링한다. 이전 API 연결 계획에서도 게시판이 추가되어도 FE 코드 변경 없이 동작하는 것을 목표로 삼았다.

문서에는 "loader에서 받은 `boards`를 버튼 토글로 렌더링하며, 현재 seed 기준 표시명은 번역/질문/자유"처럼 명시하는 편이 좋다.

### High - hidden input의 초기값과 검증 정책이 빠져 있음

F-2는 선택된 `board_code`를 hidden input으로 제출한다고 되어 있지만, 버튼 토글의 초기 선택값과 미선택 제출 방지 정책이 없다. hidden input은 기존 select의 `required` UX를 그대로 대체하기 어렵다.

다음 중 하나를 Plan에 명시하는 것이 좋다.

- 첫 번째 board 또는 기본 게시판을 초기 선택한다.
- 초기 미선택 상태를 허용하되 제출 시 view/action에서 에러를 표시한다.
- 버튼 토글을 radio group으로 구성해 HTML 폼 검증을 활용한다.

### Medium - `loader / action 변경 없음` 표현을 더 정확히 다듬을 필요가 있음

N-2와 제외 범위는 기존 loader/action/API 로직 변경 금지를 말한다. 이 방향은 타당하지만, 버튼 토글 구현에는 view 내부 상태 관리가 필요할 수 있다.

"기존 loader/action의 데이터 계약과 제출 contract는 변경하지 않는다"로 표현하면 UI 상태 추가와 서버 로직 변경 금지의 경계가 더 명확해진다.

### Medium - 시대 필드 제외 후 상단 레이아웃 정책이 모호함

목업은 글 유형과 시대를 `sm:grid-cols-2`로 나란히 배치한다. Plan은 시대 필드를 제외한다고 했지만, 제외 후 글 유형 영역을 전체 폭으로 둘지 목업의 절반 폭 구조를 유지할지 명시하지 않았다.

이번 범위에서 시대 필드를 렌더링하지 않는다면, 단일 글 유형 영역이 어색하게 반쪽 폭으로 남지 않도록 전체 폭 배치를 성공 기준에 추가하는 것이 좋다.

### Low - 검증 명령 기준이 lint와 TypeScript 사이에서 모호함

N-1은 "lint (ESLint / TypeScript) 오류 없음"으로 되어 있고 성공 기준은 `npm run lint`만 적고 있다. 프로젝트의 lint 명령이 TypeScript 타입 체크를 포함하지 않는다면 타입 검증 명령도 별도로 성공 기준에 추가하는 편이 좋다.

### Medium - 2026-05-14 수정본에서 loader 변경 범위 표현이 충돌함

수정본의 변경 파일 목록에는 `_layout.community.write.tsx`에서 loader가 `?board` 쿼리를 읽어 `defaultBoard`를 반환한다고 되어 있다. 반면 제외 범위에는 여전히 "loader / action / API 로직 변경"이 제외라고 적혀 있다.

`defaultBoard` 반환은 API 호출 로직 변경은 아니지만 loader의 반환 데이터는 바꾸는 작업이므로, 문서상 제외 범위를 더 좁게 쓰는 것이 좋다.

권장 표현:

```md
- action / API 로직 변경
- loader의 게시판 조회 로직 변경
  - 단, `?board` 쿼리 파싱 및 `defaultBoard` 반환은 이번 범위에 포함
```

또는 N-2를 다음처럼 조정할 수 있다.

```md
N-2 | action의 submit contract 변경 없음. loader의 boards 조회 contract는 유지하되 defaultBoard만 추가 반환
```

2026-05-14 재수정본에서 이 항목은 반영 완료되었다.

### Low - 비로그인 작성 진입 시 선택 탭 유지 정책은 선택적으로 보강 가능

F-3은 목록 페이지 글 작성 버튼 클릭 시 현재 탭을 `?board=`로 전달한다고 정의한다. 다만 현재 성공 기준은 로그인 사용자가 바로 `/community/write?board=...`로 이동하는 흐름 중심으로 읽힌다.

비로그인 사용자가 특정 탭에서 글 작성 버튼을 누르면 로그인 페이지로 이동한 뒤 다시 작성 화면으로 돌아와야 한다. 이때 선택 탭까지 유지하려면 로그인 redirect 값에 `/community/write?board=...`를 포함하는 기준이 필요하다.

운영 UX를 더 정확히 고정하려면 성공 기준에 다음 항목을 추가할 수 있다.

```md
- [ ] 비로그인 사용자가 특정 탭에서 글 작성 클릭 → 로그인 후 `/community/write?board=...`로 복귀해 해당 board가 선택됨
```

### Low - boards 빈 배열 fallback 정책은 선택적으로 보강 가능

F-2는 쿼리가 없거나 유효하지 않은 경우 첫 번째 board를 선택한다고 정의한다. 하지만 게시판 API 실패 또는 작성 가능한 게시판이 없는 경우에는 첫 번째 board가 존재하지 않는다.

게시판 API가 정상 운영된다는 전제라면 필수 보완은 아니지만, 구현자가 UI 상태를 명확히 처리하도록 다음 기준을 추가할 수 있다.

```md
- [ ] 작성 가능한 board가 없으면 글 유형 선택 영역에 안내를 표시하고 제출 버튼을 비활성화
```

## 확인 완료 항목

- 최초 Plan에서 변경 대상 파일을 `apps/client/app/views/community/CommunityWriteView.tsx`로 제한한 것은 UI 정렬 범위와 맞다.
- 2026-05-14 수정본에서 `?board` 연동을 추가하면서 `CommunityListView.tsx`, `_layout.community.write.tsx`가 변경 파일에 포함된 것은 요구사항과 맞다.
- 2026-05-14 재수정본에서 loader 범위 충돌은 N-2와 제외 범위 수정으로 해소되었다.
- `max-w-3xl`에서 `max-w-4xl`로 변경하는 요구사항은 현재 구현과 목업 차이를 정확히 짚고 있다.
- 카드 헤더를 회색 배경 영역으로 분리하는 요구사항은 목업 구조와 일치한다.
- "시대" 필드를 BoardCategory API 이후로 미루는 제외 범위는 적절하다.

## 권장 보완

- F-1을 API 기반 동적 버튼 렌더링 요구사항으로 수정
- F-2에 초기 선택값과 미선택 제출 검증 정책 추가
- 접근성 기준으로 `aria-pressed` 또는 radio semantics 명시
- 시대 필드 제외 후 글 유형 영역의 반응형 배치 기준 추가
- `npm run lint`가 타입 체크를 포함하지 않는 경우 타입 검증 명령 추가
- 2026-05-14 수정본 기준으로 제외 범위의 "loader 변경 없음" 문구를 `defaultBoard` 반환 추가와 충돌하지 않게 수정
- 비로그인 로그인 복귀 시 `?board` 유지 여부를 성공 기준에 추가할지 검토
- 작성 가능한 board가 없을 때 UI fallback 정책을 성공 기준에 추가할지 검토

---

## 결론

Plan은 구현 착수 가능한 수준이다. 다만 버튼 토글 항목을 하드코딩하지 않는다는 점과 hidden input 제출 정책은 구현 결과에 직접 영향을 주므로, Design 단계로 넘어가기 전에 먼저 문서에 반영하는 것을 권장한다.

2026-05-14 재수정본은 기존 리뷰 포인트를 대부분 해소했고, loader 범위 충돌도 정리되었다. 현재 Plan은 구현 착수 가능한 상태다. 남은 항목은 비로그인 로그인 복귀 시 선택 탭 유지와 boards 빈 배열 fallback 같은 운영 엣지 케이스 보강 여부다.
