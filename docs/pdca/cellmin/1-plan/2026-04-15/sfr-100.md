## 1. 목표 및 범위

### 목표
FastAPI + PostgreSQL 환경에서 Alembic 마이그레이션 파이프라인이 정상 동작함을 확인한다.
이후 모든 SFR에서 모델 작성 후 Alembic으로 마이그레이션하는 패턴의 기반을 검증한다.

### 범위
- 로컬 PostgreSQL 연결 확인 (`.env` 접속 정보 기반)
- Alembic `revision --autogenerate` 실행 확인 (빈 마이그레이션)
- Alembic `upgrade head` 실행 확인 (`alembic_version` 테이블 생성)

### 범위 외
- 실제 도메인 모델 작성 (각 SFR에서 담당)
- Docker Compose PostgreSQL (추후 전환)

## 2. 요구사항

| # | 요구사항 | 유형 |
|---|---------|------|
| 1 | 로컬 PostgreSQL에 `haedok` DB 및 유저가 존재해야 함 | 환경 |
| 2 | `.env`의 DB 접속 정보가 올바르게 설정되어야 함 | 환경 |
| 3 | `alembic revision --autogenerate -m "init"` 에러 없이 실행 | 기능 |
| 4 | `alembic upgrade head` 성공, `alembic_version` 테이블 확인 | 기능 |
| 5 | `alembic current` 로 현재 revision 확인 가능 | 기능 |

---

## 3. 성공 기준

- [ ] `uv run alembic revision --autogenerate -m "init"` → `versions/` 에 파일 생성
- [ ] `uv run alembic upgrade head` → 성공 (에러 없음)
- [ ] PostgreSQL에서 `alembic_version` 테이블 확인
- [ ] `uv run alembic current` → 현재 revision 출력

---

## 4. 제약 조건

- PostgreSQL은 로컬 설치 버전 사용 (Docker는 추후)
- 모델이 비어있으므로 autogenerate 결과는 빈 마이그레이션이어야 함
- `alembic.ini`의 `sqlalchemy.url`은 `.env` 기반 동적 설정 (`env.py`에서 override)
