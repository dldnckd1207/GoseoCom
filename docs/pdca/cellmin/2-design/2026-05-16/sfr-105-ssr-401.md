## 2. server.ts 구현

```ts
import { redirect } from 'react-router';
import { API_ENDPOINTS } from './endpoints';
import { ApiError } from './client';
import type { ApiWrappedResponse } from './client';

const BASE_URL = import.meta.env.VITE_API_BASE_URL ?? 'http://localhost:8000';

export async function serverFetch<T>(
    request: Request,
    path: string,
    init?: RequestInit,
): Promise<T> {
    const cookie = request.headers.get('cookie') ?? '';
    const res = await fetch(`${BASE_URL}${path}`, {
        ...init,
        headers: { cookie, 'Content-Type': 'application/json', ...init?.headers },
    });

    if (res.status === 0 || res.status >= 502) {
        throw new ApiError('NETWORK_ERROR', '서버에 연결할 수 없습니다.', res.status);
    }

    if (res.status === 401) {
        const url = new URL(request.url);
        const currentPath = `${url.pathname}${url.search}`;
        const loginRedirect = `/login?redirect=${encodeURIComponent(currentPath)}`;

        const refreshRes = await fetch(`${BASE_URL}${API_ENDPOINTS.AUTH_REFRESH}`, {
            method: 'POST',
            headers: { cookie },
        });

        if (!refreshRes.ok) {
            throw redirect(loginRedirect);
        }

        // 다중 Set-Cookie 처리 (access_token + refresh_token)
        const setCookieHeaders = refreshRes.headers.getSetCookie?.() ?? [];
        if (setCookieHeaders.length === 0) {
            // 쿠키 없으면 무한 redirect 방지를 위해 login으로
            throw redirect(loginRedirect);
        }

        const headers = new Headers({ Location: request.url });
        setCookieHeaders.forEach((value) => headers.append('Set-Cookie', value));
        throw new Response(null, { status: 302, headers });
    }

    const json: ApiWrappedResponse<T> = await res.json();
    if (!json.header.success) {
        throw new ApiError(json.header.code, json.header.message, res.status);
    }
    return json.body.data as T;
}
```

## 3. route catch 보정 패턴

`serverFetch`가 throw하는 `Response`(302 redirect)를 삼키는 broad catch에 아래 가드 추가:

```ts
} catch (err) {
    if (err instanceof Response) throw err;   // redirect 전파
    // 기존 에러 처리 유지
}
```

**적용 대상 (전체 일괄 적용):**
- `_protected.library._index.tsx` loader catch
- `_protected.translate.tsx` action의 번역 시작 catch
- `_layout.tsx` optional auth catch
- `_layout.community._index.tsx` ME/BOARDS_LIST/POSTS_LIST catch
- `_layout.community.$id.tsx` ME catch + 댓글 작성 action catch
- `_layout.community.write.tsx` ME/BOARDS_LIST/게시글 작성 action catch

## 4. 흐름 상세

| 케이스 | 동작 |
|--------|------|
| 정상 (200) | 기존과 동일, 데이터 반환 |
| 401, refresh 성공, Set-Cookie 있음 | 302 redirect (Set-Cookie 포함) → 브라우저 재요청 → 정상 렌더링 |
| 401, refresh 실패 | `/login?redirect=pathname+search` |
| 401, refresh 성공 + Set-Cookie 없음 | `/login?redirect=pathname+search` (무한 redirect 방지) |
| 네트워크 오류 (0, 502+) | ApiError throw (기존 동작 유지) |
| 기타 에러 (400, 403, 404 등) | ApiError throw (기존 동작 유지) |

---

## 5. 테스트 전략

수동 테스트 케이스:
1. access token 만료 + refresh token 유효 → 현재 URL 302, access/refresh 쿠키 모두 전달
2. refresh token 만료 → `/login?redirect=pathname+search` (query string 보존 확인)
3. `/library?tab=failed&page=2`에서 만료 → 로그인 후 `?tab=failed&page=2` 보존 확인
4. broad catch route에서 redirect Response가 rethrow되는지 확인 (최소 /community, /community/:id, /community/write 각 1케이스씩)
5. refresh 200 + Set-Cookie 없음 → login으로 이동 (무한 redirect 없음)
