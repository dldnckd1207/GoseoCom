## 최종 판단

승인 가능.

SFR-101은 Phase 1 구현 기준 문서로 사용할 수 있는 수준까지 정리되었다. 이전 리뷰에서 반복적으로 지적했던 큰 축의 문제는 해소되었다.

- 파일 첨부 Phase 1 범위 반영
- `file_ids` 작성/수정 스키마와 검증 정책 정리
- 파일 소유권, 삭제 파일, 첨부 정책 에러 정의
- 수정 시 파일 검증 선행 및 트랜잭션 롤백 명시
- `read_yn`/`guest_read_yn` 권한 분기 정리
- ADMIN 권한 Phase 정책 정리
- `USR_00000000` 표기 통일
- PostHistory Phase 1 정책 정리
- root 댓글 삭제 placeholder 정책 정리
- 댓글 목록 `total`과 `post.comment_count` 차이 명시
- 상위 SRS/Domain의 주요 파일 API 경로와 단위 정합성 보정

## 잔여 참고 사항

아래 항목은 구현을 막을 정도의 문제는 아니며, 필요 시 구현 단계에서 보완하면 된다.

### 1. Domain의 `comment_count` 설명은 SFR-101보다 덜 구체적임

`SFR-101`은 `comment_count`를 "삭제되지 않은 전체 댓글+대댓글 수"로 명확히 정의했다. 반면 `04_Domain.md`는 아직 "댓글 수 캐시" 또는 "댓글 추가/삭제 시 자동 증감" 수준이다.

필수 수정은 아니지만, 나중에 혼선을 줄이려면 Domain에도 SFR-101과 같은 정의를 반영하는 것이 좋다.

### 2. 게시글 삭제 시 댓글 처리 미결은 유지되어 있음

문서의 미결/리스크에 "게시글 삭제 시 연결된 댓글 처리"가 남아 있다. 현재 정책은 게시글 soft delete 후 조회 API에서 게시글 자체가 미노출되므로 Phase 1 구현에는 문제가 없다.

이 항목은 구현 차단 이슈가 아니라 운영/관리 기능 확장 시 다시 볼 항목으로 판단한다.
