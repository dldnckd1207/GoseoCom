## 1. 제품 비전

> 고서(한문/한글 고문서) 이미지를 업로드하면 OCR과 AI를 통해 직역/의역을 자동 제공하고, 커뮤니티 게시판에서 고서 관련 질문과 토론이 이루어지는 통합 플랫폼

---

## 2. 배경 및 목적

### 2.1 배경

- 한문 고서는 일반인이 접근하기 어려운 영역으로, 전문가 없이는 내용 파악이 불가능에 가깝다.
- 기존 OCR 서비스는 현대 문서에 최적화되어 있어 고서/고문서에 대한 인식률과 번역 품질이 낮다.
- 고서에 관심 있는 사람들이 질문하고 지식을 공유할 수 있는 전문 커뮤니티가 부재하다.

### 2.2 목적

- 고서 이미지를 업로드하면 **자동으로 텍스트를 추출**하고, **직역과 의역을 분리하여 제공**한다.
- 번역 결과를 사용자가 **직접 수정**할 수 있어 집단 지성을 통한 품질 향상이 가능하다.
- 커뮤니티 게시판에서 고서 관련 질문 시 **AI가 자동으로 답변**을 생성하여 응답 공백을 줄인다.

## 3. 대상 사용자

### 3.1 사용자 유형

| 사용자 유형 | 설명 | 주요 니즈 |
|----------|------|----------|
| **대학생 A** | 한문학/역사학 전공, 과제를 위해 고서를 읽어야 함 | 빠른 번역, 직역/의역 비교, 핵심 요약 |
| **일반인 B** | 고서/역사에 관심 있는 취미 학습자 | 쉬운 UI, 의역 중심의 이해, 커뮤니티 질문 |
| **동아리/스터디 C** | 고서 읽기 모임, 함께 번역 결과를 공유하고 토론 | 결과 저장/공유, 게시판 토론 |

### 3.2 사용자 특성

- 한문 지식이 없거나 제한적인 사용자가 대다수
- 모바일보다 PC 환경에서 사용할 가능성이 높음 (고서 이미지 업로드, 긴 텍스트 열람)
- 전문 연구자는 초기 대상에서 제외하되, 데이터 축적 후 확장 가능

## 4. 핵심 기능

### 4.1 기능 목록 및 우선순위

| 우선순위 | 기능 | 설명 |
|----------|------|------|
| **Must** | 다중 게시판 CRUD | 게시판 유형별(LIST/IMAGE/QNA) 글 작성/조회/수정/삭제, 파일 첨부(file/file_map 다형 매핑) |
| **Must** | OAuth 로그인 | Google/Kakao 로그인, 비로그인 사용자는 읽기만 가능 |
| **Must** | 고서 번역기 (이미지 1장) | OCR + AI 직역/의역, 파이프라인의 정식 진입점 |
| **Must** | 라이브러리 | 로그인 사용자의 번역 이력 조회 (Book 단위) |
| **Must** | AI 자동 답변 (텍스트) | 설정 시간 경과 + 댓글 0건 게시글에 AI가 텍스트 기반 답변 |
| **Should** | AI 자동 답변 (파이프라인) | 파이프라인 ON 게시판의 자동 답변에 OCR+번역 포함 (Phase 2) |
| **Should** | PDF 다중 페이지 번역 | 이미지 단건 파이프라인 확장 (Phase 2) |
| **Should** | 번역 결과 수정 (본인만) | 본인 소유 Book의 직역/의역 편집, 이력 보존 |
| **Should** | 핵심 요약 / 키워드 / 빈도수 | Book 단위 요약(LLM) + 키워드/빈도수(kiwipiepy 로컬) |
| **Should** | 결과 저장 / 공유 | UUID 토큰 기반 공유 링크, 열람 전용 |
| **Should** | 라이브러리 확장 | 탭 구조(내 책/빠른 번역), 즐겨찾기, 제목 검색 (Phase 2) |
| **Should** | 관리자 페이지 | 게시판/게시글/댓글/사용자 관리 (Phase 3) |
| **Could** | 악성댓글 필터링 | 주기적 AI 검수, 필터링 UI, 관리자 해제 (Phase 3) |
| **Could** | 참고자료 추천 | 구현 방식 Phase 3 회의에서 확정 |
| **Could** | 타인 번역 제안 | 공유 Book에 수정 제안 등록 (Phase 3) |

### 4.2 사용자 스토리

#### 게시판 + AI 자동 댓글

- **US-01**: 사용자로서, 게시판에 글을 작성하고 고서 이미지를 첨부하고 싶다, 번역을 받기 위해.
- **US-02**: 사용자로서, 글 작성 후 자동으로 OCR + 번역 결과가 댓글로 달리길 원한다, 전문가 없이도 내용을 파악하기 위해.
- **US-03**: 사용자로서, 고서 관련 질문글을 올렸을 때 빠른 답변을 받고 싶다, 학습 흐름이 끊기지 않기 위해.

#### OCR 번역 파이프라인

- **US-04**: 사용자로서, OCR 결과의 직역과 의역을 나란히 비교하고 싶다, 원문의 뉘앙스를 파악하기 위해.
- **US-05**: 사용자로서, 잘못된 번역을 직접 수정하고 싶다, 정확한 번역을 축적하기 위해.
- **US-06**: 사용자로서, 핵심 요약과 키워드를 한눈에 보고 싶다, 문서의 주제를 빠르게 파악하기 위해.

#### 고서 번역기

- **US-09** (Phase 1): 사용자로서, 번역기에서 고서 이미지를 올려 바로 번역 결과를 보고 싶다, 게시판 없이 빠르게 번역하기 위해.
- **US-10** (Phase 2): 사용자로서, 번역 결과를 저장하고 링크로 공유하고 싶다, 스터디 멤버와 함께 보기 위해.

#### 관리 기능 (Phase 3)

- **US-07**: 관리자로서, AI 자동 답변 대기 시간을 설정하고 싶다, 커뮤니티 상황에 맞게 조절하기 위해.
- **US-08**: 관리자로서, AI가 필터링한 악성댓글을 확인하고 삭제 조치하고 싶다, 건전한 커뮤니티를 유지하기 위해.

## 5. 사용자 흐름 (User Flow)

### 5.1 고서 번역기 흐름

```
[사용자]                    [프론트엔드]              [백엔드]                    [AI 파이프라인]
   |                           |                        |                            |
   |-- 이미지/텍스트 입력 ----->|                        |                            |
   |                           |-- POST /translate ----->|                            |
   |                           |                        |-- 이미지 전달 -------------->|
   |                           |                        |                            |-- OCR 실행 (PaddleOCR)
   |                           |                        |                            |-- 텍스트 추출
   |                           |                        |                            |-- AI 직역/의역 (Gemini Flash)
   |                           |                        |<-- 번역 결과 반환 ------------|
   |                           |<-- 결과 반환 ------------|                            |
   |<-- 결과 표시 -------------|                        |                            |
```

### 5.2 커뮤니티 게시판: AI 자동 답변 흐름

```
[스케줄러]                                  [백엔드]                    [AI 파이프라인]
   |                                          |                            |
   |-- 주기적 확인 (1분 간격) ----------------->|                            |
   |                                          |-- 답글 없는 글 조회          |
   |                                          |-- 작성 후 5분 경과 확인       |
   |                                          |-- 글 내용 전달 ------------->|
   |                                          |                            |-- AI 답변 생성
   |                                          |                            |   (이미지 첨부 시 OCR + 번역 포함)
   |                                          |<-- 답변 반환 ----------------|
   |                                          |-- 자동 댓글 등록             |
```

### 5.3 커뮤니티 게시판: 악성댓글 필터링 흐름 (Phase 3)

```
[스케줄러]                                  [백엔드]                    [AI 파이프라인]
   |                                          |                            |
   |-- 주기적 검수 (설정 주기) ----------------->|                            |
   |                                          |-- 미검수 댓글 조회           |
   |                                          |-- 댓글 내용 전달 ----------->|
   |                                          |                            |-- 악성 여부 판별
   |                                          |<-- 판별 결과 반환 ------------|
   |                                          |-- 악성: 필터링 표시           |
   |                                          |-- 정상: 검수 완료 처리        |
```

## 6. 비기능 요구사항

| 항목 | 요구사항 |
|------|---------|
| **성능** | OCR + 번역 파이프라인 응답 시간 30초 이내 (A4 1페이지 기준) |
| **성능** | 게시판 API 응답 시간 500ms 이내 |
| **가용성** | Docker Compose 기반 배포, 로컬/클라우드 환경 모두 지원 |
| **확장성** | OCR 엔진을 인터페이스로 추상화하여 엔진 교체 가능 |
| **보안** | 업로드 파일 타입/크기 제한 (이미지만, 최대 10MB) |
| **보안** | XSS, SQL Injection 방지 |
| **호환성** | 최신 Chrome, Edge, Firefox 지원 |
| **데이터** | 번역 결과 및 게시글 데이터 영속적 저장 (PostgreSQL) |

## 7. 제약 조건 및 가정

### 7.1 제약 조건

- OCR 엔진(PaddleOCR)의 고문서 인식률이 현대 문서 대비 낮을 수 있음 (인식률 부족 시 Google Vision API로 전환 가능)
- AI 번역 품질은 모델(Gemini Flash / Claude Haiku)의 한문 이해도에 의존
- 무료 API 사용 시 호출 제한(Rate Limit)이 존재할 수 있음

### 7.2 가정

- 사용자가 업로드하는 고서 이미지는 촬영/스캔 상태가 판독 가능한 수준임
- 한문(한자) 및 한글 고문서를 대상으로 하며, 일본어/기타 언어는 범위 외
- 3명이 프론트엔드/백엔드/AI 파이프라인을 분담하여 병렬 개발

### 7.3 기술 스택

| 영역 | 기술 |
|------|------|
| **프론트엔드** | React / Remix |
| **백엔드** | FastAPI (Python) |
| **데이터베이스** | PostgreSQL |
| **OAuth** | Google + Kakao |
| **OCR 엔진** | 1순위: PaddleOCR / 2순위: Google Vision API |
| **AI 모델** | 1순위: Gemini Flash (무료) / 2순위: Claude Haiku (유료) |
| **형태소 분석 (키워드/빈도수)** | kiwipiepy |
| **배포** | Docker Compose |

## 9. 범위 외 (Out of Scope)

- 모바일 앱 (웹 반응형으로 대체)

- OCR 모델 직접 학습/파인튜닝
- 논문 파일 자체 호스팅 (링크만 제공)

### 향후 확장 가능

- 다국어 고문서 지원 (일본어, 중국어 등)
- 모바일 네이티브 앱
- OCR 모델 파인튜닝을 통한 인식률 개선

## 10. 용어 정의

| 용어 | 정의 |
|------|------|
| **고서** | 한문 또는 한글로 작성된 역사적 문서 (고문서, 고전 문헌) |
| **OCR** | Optical Character Recognition, 이미지에서 텍스트를 인식/추출하는 기술 |
| **직역** | 원문의 글자를 그대로 한글로 대응하여 번역한 결과 |
| **의역** | 원문의 의미를 현대 한국어로 자연스럽게 풀어 번역한 결과 |
| **파이프라인** | OCR → 번역 → 요약 → 댓글 생성까지의 자동화된 처리 흐름 |
| **AI 자동 답변** | 설정된 시간 내 사용자 답글이 없을 경우 AI가 생성하는 답변 |
| **필터링 댓글** | AI가 부적절하다고 판별하여 숨김 처리된 댓글 |

## 11. 개발 Phase 로드맵

### Phase 1 (MVP, 시연 가능)

- 모노레포 / Docker Compose 기반 구축 (apps/client, apps/server, apps/admin 스캐폴드)
- OAuth 로그인 (Google + Kakao) — 비로그인 글쓰기 차단
- 다중 게시판 스키마 + LIST 유형 UI
- 게시글/댓글 CRUD (작성자 FK 연결)
- 파일 업로드 (file + file_map 다형 매핑, 업로드/엔티티 생성 API 분리)
- **고서 번역기 (이미지 1장, 파이프라인 정식 진입점)** — OCR + AI 직역/의역
- 라이브러리 (단순 리스트, 본인 Book 조회)
- AI 자동 답변 (텍스트 기반) + 게시판별 설정(활성화, 대기 시간)
- 로그 스키마 선반영 (login_log, admin_audit_log)

### Phase 2

- 고서 번역기 확장: PDF 다중 페이지 (최대 100페이지/50MB), 사용자 등록 Book
- 게시판 UI 확장: IMAGE(카드/갤러리), QNA(아코디언) 유형
- 게시판-파이프라인 연동 자동 답변 (`board.pipeline_enabled` ON)
- 번역 결과 수정 (본인 소유만, 이력 보존)
- 요약 / 키워드 / 빈도수 (Book 단위, 자동)
- 번역 결과 저장 / 공유 (UUID 토큰 기반 공유 링크)
- 라이브러리 확장 (탭 구조, 즐겨찾기, 제목 검색)

### Phase 3

- 관리자 페이지 (`apps/admin`) — 게시판/게시글/댓글/사용자 관리 (1차 표준)
- 권한 데코레이터 활성화 (ADMIN / SYSTEM_ADMIN)
- 관리자 로그 뷰어 (login_log / admin_audit_log)
- 악성댓글 AI 필터링 (주기적 배치, "내용 보기" 토글, 관리자 해제)
- 참고자료 추천 (구현 방식 착수 시 확정)
- 타인 번역 제안 (suggestion) 플로우
- 시간 여유 시: 시스템 로그 뷰어, 파이프라인 재실행, 엔진 전환 UI (SYSTEM_ADMIN 전용)

## 12. 팀 구성 및 역할

| 역할 | 담당 범위 |
|------|----------|
| **프론트엔드 개발** | React / Remix 게시판 UI, OCR 결과 표시/편집 화면, 반응형 레이아웃 |
| **백엔드 개발** | FastAPI REST API, 게시판 CRUD, DB 설계, 스케줄러, 파일 업로드 |
| **AI 파이프라인 개발** | PaddleOCR 연동, AI 번역 API 호출, 자동 댓글/답변 생성 로직 |
